The chart component and the drawing parts behind its adapters.

## `Chart`

The one chart (#639): the only component the app uses to draw one. A figure with its title and takeaway, the drawing from whichever adapter the registry picks for the kind, the colour key, a caption (what a unit means, when, where from, how sure) and, under it, the same numbers as a table that starts closed. The spec is checked first, so a chart that does not add up is an error and never a wrong picture.

## `ChartZoom`

Lets a reader enlarge a chart (#681). The chart is a thumbnail in the page; "Enlarge", or a click or tap on the drawing, opens the same server-rendered chart in the shared `Zoom` (#815), so there is one drawing, one set of ids and one data table at any moment, and no picture is made. The chart's layout reads this wrapper's width (`@container/chart`), here and in the dialog. This is the only client code of the chart: it imports no chart library.

## `ScaledBreakdown`

A breakdown chart drawn in the browser with every amount multiplied by `factor` (#1020): the City's tax on the home a reader typed, split the way the budget is. It is the same figure as `Chart` draws for a breakdown (title, takeaway, the drawing, the caption) from the same drawing code, but it takes a spec that was already checked on the server and never parses it, so no spec rules (zod) and no chart library reach the browser; `ScaledBreakdown.test.tsx` guards that. Every figure is text in the drawing, so it has no separate numbers table. Each time `fillKey` changes (a row that holds it opening), the bars grow and the amounts count up from nothing, while the percents stay put; `compact` draws thinner bars, for a breakdown inside a bill (#1163).
